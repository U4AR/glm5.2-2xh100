The decomposition closes to the millisecond: 52.68 + 1.76 + 9.24 + 0.21 = 63.89. The CPU expert path collapses from 13.39 to 0.21 ms — the sliver at the right edge above.

What the machinery costs when it cannot help

Tier 0 substitutes every expert with a GPU-resident one, so there is no CPU work to save — but the predictor still fires and the gather still moves bytes. That isolates the overhead exactly.

So the prefetch machinery costs 11.00 ms and buys back 13.18 ms. The margin is thin not because prediction is poor, but because the transfer is nearly as expensive as the compute it displaces.

The strongest statement available is the end-to-end one: the exposed CPU expert path fell from 13.39 to 0.21 ms. Almost everything the layers needed had already landed.

One caveat on that number. Part of the collapse may be extra shadow rather than better prediction — the gather adds 24 ms of GPU work, giving the CPU more time to hide behind. This experiment does not separate the two. Per-layer recall was not re-measured today: the fused predictor bypasses the scoring instrument, so KT_PLACE_SCORE is a no-op and it needs a separate eager boot.

What this says about the ceiling

  • The CPU expert path is only 20% of the step at the shipped tier — 13.39 of 66.07 ms. The tier substitution already removed 86% of it (at top8 the same path costs 96.80 ms). A prefetcher cannot win more than what substitution left behind.
  • The gather is the expensive half. 24.20 ms/step of GPU kernel time to avoid 13.18 ms of CPU compute. It only nets positive because ~62% of it hides.
  • The 52.68 ms floor is now the target. It is 82% of the step and has nothing to do with CPU experts. Norm/rope/elemwise alone is 12.29 ms across thousands of tiny launches — this decode is priced by launch count, not FLOPs.
